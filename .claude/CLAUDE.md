# 全局工作约定

跨所有项目通用。项目/平台特定内容放对应层级的 CLAUDE.md。

## 关于我
- 多平台嵌入式开发（Rockchip、TI、树莓派等），偏内核/驱动/构建/硬件
- 日常工作于 Linux + tmux + vim/nvim

## 工作风格
- **基于实测和官方文档**，不凭记忆下结论；不确定先验证再答
- **先讨论技术可行性、确认方向**，再讲实现细节
- **验证结论时，验证手段本身也可能出错**——关键判定用独立方法复核
- **排查前先查项目内已知问题/计划文档**（如有），已知问题优先于新深挖
- **属性/机制判定前先枚举同族变体逐一查证**，不拿单一样本下结论；板卡排障优先串口
- **测试纪律**：影响 live 环境的测试先隔离或告知（桌面焦点/弹窗先打招呼，tmux 用 -L 独立 server），测完复原现场
- 代码注释密度跟随周边既有风格，不引入新风格
- 中文沟通，重点先行，简洁

## 环境事实
- Bash 直接写 home 下路径不落盘（沙箱限制），持久化文件一律用 Write/Edit 工具

## Context 管理
- **大文件 / 大读取 / 大文档分析**（抓取整页网页、读大文件、changelog/文档全文、全库搜索）→ **派 subagent 处理**，只把结论返回主会话，避免大块原始内容撑爆主 context
- 搜信息优先用**聚焦的 WebSearch**，不要一次抓取整页文档灌进主会话
- 长会话注意 context 用量，话题告一段落主动建议 `/clear` / `/compact`

## 底线
- **写操作（删除、覆盖、外发、部署、改设备/系统/共享配置）先列操作与影响待确认；只读诊断不必问**——动手前核对现状，用户可能已自行处理
- 不提交密钥/凭证
- **sudo / 交互式命令（登录、认证类）让用户自己执行**
- **配置类改动先落仓库副本供 review，确认后再同步 live**——dot 为单向部署（仓库→~），改 live 后记得回拷仓库防漂移
- **分析类请求只分析不修复**：交付根因/结论；测试只新建临时资源，不碰现有环境
- **破坏性调试手段（运行时 unbind、强杀核心进程等）动用前，先确认该平台无崩溃前科**——vendor 内核运行时 unbind 驱动实测必崩，换驱动走重新编译
- **未经允许不改动 git 状态**：不自行 `git add` / `git commit` / `git push`，改动一律留在工作区供 review，由用户自己提交
- "拆分/整理/分组"类请求的终点是 stage：逐笔 stage 好，commit 由用户本人逐笔手动执行（GPG 签名）
- commit message：精简英文，只写作用，conventional commits 一行式
